# ARGUS product simplification and visual redesign

## Audit and decisions

All 39 existing screenshots were inspected in a contact-sheet audit, with full-size desktop/mobile review of representative dashboard, explorer, prediction, SHAP, graph, investigation and evaluation states. Frontend pages/components/styles, actual API consumers and automated workflows were inspected. The main problems were tiny low-contrast typography, a permanent mobile icon rail, competing banners/cards, a long always-open 30-feature form, and every analytical panel rendering at once.

The redesign keeps the working FastAPI/React architecture and all conventional ML behavior. Review tools are grouped first: Overview, Transactions, Fraud Detection, Investigations. Model performance and the synthetic Relationship demo are secondary research tools; Settings remains administration. Hash routes are preserved, including investigation/entity deep links. Mobile uses a labeled, dismissible navigation dialog with focus containment and Escape support. A skip link focuses content without corrupting the hash route.

Removed from the primary workflow: repetitive research banners, fictitious analyst avatar, workspace version tile, pipeline illustration, command-line training panel, repeated model test statistics on Overview, decorative summed amount KPI, duplicate inline analyst-decision form and empty recent-case panel. Relevant research/provenance/uncalibrated warnings remain near the data and in the footer; reproducibility/security/schema details remain available. Thirty-one orphan selectors for retired decorations were removed. No backend endpoint or dependency was deleted speculatively; existing contracts/tests remain supported.

Overview leads with the review queue and distinguishes observed fraud labels from model flags. Transactions gives results the full width, keeps common assessment/source/search/sort controls visible and moves advanced ranges/saved queries into a disclosure. Request cancellation prevents obsolete filter requests doing unnecessary client work. CSV downloads now use the same optional API authentication as other calls and release their temporary object URLs.

Prediction starts with a stored example or a transaction deep link. Time and Amount remain visible; V1–V28 and decision overrides are disclosed on demand. All 30 original inputs are validated and transmitted unchanged when using stored rows. SHAP groups the strongest positive and negative contributions on a common magnitude scale; all contributions, base/model/output-space information remain expandable. Edits do not change the submitted explanation snapshot.

Model comparison remains first; Test results, Calibration & thresholds and Features & methodology are separate views. No saved metric, confusion matrix, validation threshold profile, model-native importance, partition metadata or export capability was removed. Investigations retain notes, status/priority, timelines, linked evidence, resizing, exports and the dedicated decision view. The graph retains explicit synthetic provenance and is not presented as ULB relationship evidence.

## Verification and performance

Local gates: 78 backend tests, 16 frontend tests, and 15 clean Chrome workflows pass. Lint/typecheck, Ruff lint/format and production build pass. The isolated Docker stack starts and its frontend/API/PostgreSQL and same-origin Swagger/OpenAPI routes pass smoke checks. New coverage includes positive/negative explanation rendering, exact-schema progressive input, recorded transaction provenance, authenticated CSV export, mobile navigation, stored transaction→prediction equivalence and keyboard scrolling of the mobile comparison table.

Vite entry JavaScript drops from approximately **287.10 kB to 239.67 kB** (87.73→75.59 kB gzip). CSS increases from48.02 to58.55 kB (11.48→13.63 kB gzip) to support readable controls, layouts and disclosure states. Entry JS+CSS gzip decreases approximately10%; route chunks are additional, so this is not a total page-transfer or latency claim. No animation/font library or remote font request was added. A fresh Chrome audit confirms Transactions requests neither Recharts nor Cytoscape; Overview and Settings request zero full `/models` reports, using the already loaded active-model metadata instead. Heavy evaluation/graph pages are lazy. Raw evidence: research/ui-redesign-verification.json.

All important pages/features have real before/after desktop1440×900 and mobile390×844 captures, with ULB and existing synthetic demonstration data clearly distinguished. See [the gallery](screenshots/README.md). Existing ML experiments/dataset were reused; prediction correctness, calibration interpretation and research limitations are unchanged. This is a polished research application, not a production banking/security certification.
